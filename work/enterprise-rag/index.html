Private Enterprise Knowledge Retrieval with Evidence and Access Control

A retrieval approach for finding permitted evidence across technical documents, SOPs and tables—with citations and explicit failure boundaries.

Who this is for

B2B and enterprise teams working with scattered internal knowledge

Outcome / boundary

A bounded knowledge pilot with an agreed evaluation set; no production accuracy, security certification or deployment claim.

Evidence & scope

Reference architecture for a bounded knowledge pilot. This page explains design decisions and proposed extensions; it does not claim a deployed enterprise RAG service or measured production performance.

The problem

A plausible answer is insufficient when staff need the exact part number, an approved procedure or a source they can inspect. Retrieval should make the supporting evidence and access boundary visible.

Business context

Knowledge may be spread across PDFs, spreadsheets, SOPs and technical documents. The pilot starts with one approved collection and a defined set of user questions, not an unrestricted assistant over every company system.

Constraints

Tables, scanned pages and exact identifiers behave differently from ordinary prose. Document permissions need a trusted identity source; metadata alone cannot authenticate a caller.

Deterministic fixture checks do not establish OCR quality, semantic retrieval relevance or production authentication. Those require an approved collection, trusted identity and separate evaluation.

Architecture

Retrieval foundations

Preserve native document structure, use OCR only when extraction quality requires it, and retain source versions and locators. Route exact identifiers and tables separately from prose. Use deterministic calculations for numeric analysis.

PostgreSQL native full-text ranking is not BM25. Hybrid retrieval can fuse lexical and dense ranks before reranking. Fusion scores are ranking signals, not confidence. This is a reference design; no retrieval benchmark is claimed.

Proposed graph-based extension

For relationships across internal projects, systems and documents, compare SQL joins and explicit relationship queries first. A graph-based extension is justified only by questions and evidence that simpler retrieval cannot handle well.

Microsoft GraphRAG adds extraction and community-based indexing and search. Extracted relationships need provenance, time validity and permission checks; a path does not establish causality. This extension has not been implemented here.

Proposed agentic retrieval extension

A bounded agent could rewrite a query, choose document, SQL or API tools, and stop when evidence is sufficient or a budget is exhausted. A single agent may be enough; more agents are not a quality guarantee.

Retrieved content is data, not permission to act. Business writes require a separate authorization and confirmation boundary. After a write timeout, reconcile an operation identifier before retrying. If the target has no reliable status or idempotency contract, keep the outcome unknown and require manual reconciliation.

Implementation status

This page documents an approach, not a deployed RAG service. The related manufacturing page demonstrates deterministic fixture lookup only. Model inference, hybrid retrieval, graph indexing, trusted identity and enterprise tool execution require separate implementation and evaluation.

Key engineering decisions

Use a parser registry to route formats and preserve page, sheet, table and section context. Detect poor extraction so an OCR fallback or manual review can be considered rather than silently indexing unusable text.

Preserve document boundaries and table structure while chunking. Combine lexical matches for identifiers with dense retrieval for paraphrases; rank fusion and reranking need evaluation against the actual questions.

Carry provenance into citations so a reader can inspect the evidence. A citation is a traceable pointer; its presence alone does not establish that the answer is supported.

Failure scenarios

No usable evidence: refuse or ask for a narrower question. Parsing failure or poor OCR: surface an ingestion issue. An exact identifier is missed: inspect parsing, metadata and lexical retrieval before changing the model.

Permission changes, stale indexes and untrusted document instructions need dedicated tests. A retrieved instruction must not expand tool permissions or override the application’s security policy.

Reliability strategy

Define test questions, allowed sources, expected refusals and exact-field cases before optimizing retrieval. Separate parser correctness, retrieval relevance, citation validity and answer support; do not combine them into one unsupported quality score.

Use bounded provider calls, explicit failure outcomes and audit records that omit raw sensitive content. Function calling, MCP and tool integration are extension boundaries here, not proof of autonomous enterprise operation.

Security & permissions

Apply authorization before evidence reaches a reranker or answer generator. Permission boundaries also cover graph-derived summaries, citations, caches and logs; source changes and access revocation require invalidation or rebuilding of affected derived data.

A private production pilot needs verified identity, access revocation behavior, tenant boundaries, secret handling and approved processing locations. These are prerequisites, not completed claims.

Trade-offs

Hybrid retrieval offers multiple ways to find evidence but adds ranking and evaluation work. Reranking adds latency and cost. OCR introduces extraction uncertainty. Strict refusal can reduce answer coverage; the trade-off must be evaluated with the client’s risk tolerance.

Expected outcome & validation

A pilot should make relevant, permitted sources easier to inspect and make missing evidence explicit. No accuracy, time-saving or production-readiness result is asserted.

The next evidence milestone is a revision-bound source and test audit, followed by a sanitized evaluation report using an approved collection. A private deployment claim follows a separate security and runtime review.
