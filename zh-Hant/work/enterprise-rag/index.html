問題

員工需要精確料號、適用程序與可核對來源；合理的語句本身不足以支持業務使用。

業務情境

資料可能分散於 PDF、Excel、SOP 與技術文件。從一組核准文件和明確問題開始，不預設跨越所有公司系統。

限制

掃描件、表格與精確識別碼和一般文章不同。權限需要可信身份來源，metadata 本身不能認證使用者。合成資料測試不代表 OCR、語意檢索或正式身份驗證品質。

系統架構

檢索基礎

原生文件解析優先，品質不足時才加入 OCR；保留版本與頁、表、段落位置。精確欄位與表格分別處理，數字用確定性計算。PostgreSQL 原生全文排名不是 BM25；詞彙與向量可經融合及重排序，但排名分數不等於信心。此處沒有檢索 benchmark。

規劃中的圖關聯延伸

跨內部專案、系統與文件的關係查詢，應先比較 SQL JOIN、明確關係查詢與混合檢索。Microsoft GraphRAG 是包含關係抽取與社群摘要的具體方案，並非所有圖檢索的共同實作。關係需要來源、有效時間與權限；圖上路徑不能證明因果。此延伸尚未實作。

規劃中的 Agent 檢索延伸

有限範圍的 agent 可改寫查詢、選擇文件／SQL／API，並在證據足夠或預算耗盡時停止。更多 agent 不保證品質。檢索內容是資料，不是操作授權；寫入須分開確認，逾時後以操作識別碼對帳再決定重試；若目標沒有可靠狀態查詢或冪等契約，保留「結果不明」並交由人工核對。

實作狀態

此頁是方法與設計說明。相關製造頁只實作確定性的合成文件查詢；模型、混合檢索、圖索引、可信身份及企業工具執行都需另外實作與評估。

工程決策

用解析器註冊表分流格式，保留頁、工作表與章節，偵測解析失敗。分塊保留文件邊界與表格，融合檢索以實際問題評估。引用提供來源位置，但有引用不代表內容支持答案。

故障情境

無可用證據時拒答或縮小問題；解析或 OCR 不良時回報匯入問題。遺漏識別碼先查解析、metadata 與詞彙檢索。權限變更、過期索引及文件中的不可信指令都需要專項測試。

可靠性策略

先定義問題、允許來源、應拒答與精確欄位案例。分別評估解析正確性、檢索相關性、引用有效性和答案支持程度。限制外部呼叫並保留不含敏感原文的稽核紀錄；工具整合只是延伸邊界。

安全與權限

證據送到重排序模型或回答模型前就要完成授權。圖譜衍生摘要、引用、快取和日誌也須遵守權限；來源變更與撤權後，要使受影響資料失效或重建。正式部署須驗證身份、租戶隔離、密鑰與資料處理位置。

取捨

混合檢索與重排序增加評估、延遲及成本；OCR 帶來抽取不確定性；嚴格拒答降低回答覆蓋率。應按客戶風險容忍度衡量。

預期成果與驗收

以固定評測集驗證召回、來源支持、拒答與存取案例。沒有生產準確率承諾；先完成一組文件的可核對試作，再決定擴展。
